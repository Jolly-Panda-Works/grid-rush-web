# Grid Rush — نسخه‌ی وب (React Three Fiber + Colyseus)

بازی دونفره‌ی Tile Placement رقابتی، طبق `01_GDD.md`، `02_Core_Rules.md` و هویت بصری `21_Branding.md`.

## اجرا (لوکال)

نیازمندی: Node.js 18 یا بالاتر.

```bash
npm install
npm run dev
```

سپس `http://localhost:5176` را باز کنید. سرور Colyseus روی پورت 2567 بالا می‌آید.
برای تست دو بازیکن واقعی، دو تب (یا دو مرورگر) باز کنید و در هر دو «Find match» بزنید.

نسخه‌ی build شده (سرور خودش کلاینت را سرو می‌کند):

```bash
npm start     # build + اجرا روی http://localhost:2567
```

سایر دستورها: `npm run typecheck`، `npm run test:bots` (بازی بات‌ها با هم)، `npm run smoke -w server` (تست اتصال واقعی Colyseus؛ سرور باید روشن باشد).

## جریان بازی

1. **Loading**: فونت‌ها، بررسی سلامت سرور، نکته‌ی آموزشی.
2. **Menu**: نام، سطح، XP، رتبه، «Find match»، «Play vs bot»، راهنما، تنظیمات (صدا / Reduce motion).
3. **Matchmaking**: `joinOrCreate` در Colyseus. اگر طی ۷ ثانیه حریف پیدا نشود بات اضافه می‌شود (`MATCH_WAIT_MS` با متغیر محیطی قابل تغییر است).
4. **Game**: صفحه‌ی ۹×۹ هر دو بازیکن + مسیر زمان مشترک سه‌بعدی + HUD.
5. **Results**: ریز امتیاز (سکه + بونوس ۷×۷ − جریمه‌ی خانه‌ی خالی)، تغییر رتبه (Elo)، XP و سطح.

## معماری

- `shared/`: منطق قوانین (`engine.ts`)، بات (`bot.ts`)، کاشی‌ها، ثابت‌ها. سرور و کلاینت هر دو از آن استفاده می‌کنند.
- `server/`: اتاق Colyseus (`GridRushRoom.ts`) به‌صورت server-authoritative. هر حرکت در سرور اعتبارسنجی و اجرا می‌شود و state برای دو طرف broadcast می‌شود.
- `client/`: React + R3F + Zustand. ماوس: hover و کلیک. لمس: یک تپ پیش‌نمایش، تپ دوم تأیید.
- میان‌برها: `1-3` انتخاب کاشی، `R` چرخش، `F` آینه‌ی افقی، `V` آینه‌ی عمودی، `A` Advance، `Esc` لغو.

### سختی بات
`botTierFor(level, rating)` در `shared/src/bot.ts` پنج درجه می‌دهد (Rookie تا Master). درجه‌های پایین با احتمال حرکت تصادفی و نویز بیشتر بازی می‌کنند. درجه‌های بالا پایان بازی را پیش‌بینی می‌کنند و از ساختن حفره‌های غیرقابل‌پر پرهیز می‌کنند. رتبه‌ی نمایشی بات نزدیک به رتبه‌ی بازیکن است تا Elo معنا داشته باشد.

### پیشرفت بازیکن
سطح، XP، رتبه و آمار برد/باخت در `localStorage` مرورگر ذخیره می‌شود (بدون دیتابیس).

## نکات صادقانه

- **قانون Advance (نسخه‌ی ۰.۴، تغییر نسبت به `02_Core_Rules.md`):** بازیکن دقیقاً به «موقعیت حریف + ۱» می‌رود و به‌ازای هر خانه‌ی جابه‌جاشده ۱ سکه می‌گیرد. فرمول قبلی (`Position + Opponent + 1`) حذف شد. این تغییر حلقه‌ی خودتقویت‌شونده را از بین می‌برد. بخش ۳.۲ و ۴.۳ سند قوانین و GDD باید با این قانون به‌روزرسانی شوند.
- در خودبازی بات‌ها (`npm run test:bots`) درجه‌های بالاتر به‌طور محسوس بیشتر می‌برند (Rookie حدود ۳۸ برد، Master حدود ۷۷ برد در ۳۰۰ بازی). تنظیم دقیق سختی نیاز به پلی‌تست انسانی دارد.

## اندروید (GitHub Actions)

بازی فقط **افقی** اجرا می‌شود. در حالت عمودی صفحه‌ی «دستگاه را بچرخان» نمایش داده می‌شود و اپ اندروید هم روی `sensorLandscape` قفل است. خروجی اندروید با Capacitor ساخته می‌شود (پروژه‌ی اندروید در `client/android` است) و workflow آن در `.github/workflows/android.yml` است.

**ساخت APK دیباگ (بدون هیچ تنظیمی):** در GitHub به Actions → «Android build» → Run workflow بروید، `debug-apk` را انتخاب کنید. بعد از چند دقیقه فایل APK در بخش Artifacts همان run قرار دارد. هر Pull Request هم که به `client/` یا `shared/` دست بزند همین ساخت را اجرا می‌کند.

**ساخت نسخه‌ی release (APK یا AAB برای گوگل‌پلی):**

1. یک keystore بسازید: `keytool -genkeypair -v -keystore gridrush.jks -alias gridrush -keyalg RSA -keysize 2048 -validity 10000`
2. در Settings → Secrets and variables → Actions این Secretها را بسازید:
   `ANDROID_KEYSTORE_BASE64` (خروجی `base64 -w0 gridrush.jks`)، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`، `ANDROID_KEY_PASSWORD`
3. workflow را با `release-apk` یا `release-aab` اجرا کنید، یا یک تگ بزنید (`git tag v1.0.0 && git push --tags`). با تگ، فایل AAB به Release هم پیوست می‌شود.

keystore را جای امن نگه دارید. اگر گم شود، نمی‌توانید آپدیت همان اپ را منتشر کنید.

**آدرس سرور بازی:** اپ اندروید روی گوشی است، پس `localhost` معنی ندارد و باید سرور Colyseus جای قابل‌دسترسی (VPS یا هر میزبانی) اجرا شود. دو راه:
- در Variables ریپو `SERVER_URL` را بگذارید (مثلاً `wss://game.example.com`) تا داخل اپ ساخته شود.
- یا خالی بگذارید: در منوی اپ فیلد «آدرس سرور» نمایش داده می‌شود و بازیکن آدرس را وارد می‌کند (مثلاً `192.168.1.20:2567` برای تست روی شبکه‌ی خانگی). این آدرس روی دستگاه ذخیره می‌شود.

برای تست محلی: `npm run dev` را روی کامپیوتر اجرا کنید و آدرس IP کامپیوتر را با پورت ۲۵۶۷ در اپ وارد کنید. اپ برای ارتباط ساده‌ی `ws://` روی شبکه‌ی داخلی تنظیم شده است. برای محیط واقعی از `wss://` استفاده کنید.

اگر ریشه‌ی ریپوی شما همین پوشه نیست (مثلاً این پروژه داخل یک زیرپوشه است)، فایل `.github/workflows` باید در ریشه‌ی ریپو باشد و مسیرهای `client/...` در آن با زیرپوشه هماهنگ شوند.

باز کردن پروژه در Android Studio: `npm run build -w client` سپس `npm run cap:sync -w client` و `npm run android:open -w client`.
